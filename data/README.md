# 사전 수집 데이터

`scripts/collect.ts` 가 채우는 파일이다. **비어 있어도 앱은 동작한다** — 그때는
런타임에 KTO API 를 직접 부른다. 파일이 채워져 있으면 그쪽을 먼저 쓴다.

| 파일 | 내용 | 채우는 API |
|---|---|---|
| `places.json` | 전국 장소 목록 9,691건 | `petTourSyncList2` 1콜 |
| `petRules.json` | 동반 조건 (쇼핑 제외 1,044곳) | `detailPetTour2` 곳당 1콜 |
| `details.json` | 영업시간·휴무일·전화·소개글·사진·입장료 | `detailCommon2`/`Intro2`/`Info2`/`Image2` 곳당 4콜 |

## 왜 파일로 두나

배포 환경(Vercel 등)은 파일시스템이 읽기 전용이라 런타임에 캐시를 파일로 쓸 수 없다.
반면 **빌드에 포함된 파일을 읽는 것은 어디서든 동작한다.** 그래서 수집은 로컬에서
하고 결과를 커밋한다.

이렇게 하면 콜드 스타트 7.3초가 0초가 되고, KTO 가 장애를 겪어도 서비스가 살아 있다.
배치가 하루 한 번 도니 API 호출 이력도 계속 쌓인다.

표에 없는 장소(쇼핑 등 수집 대상 밖)는 화면에서 실시간으로 부른다 — 파일은 대체재가
아니라 앞단이고, 실시간 경로는 그대로 살아 있다.

## 채우는 법

```bash
npm run collect
```

`detailPetTour2` 는 장소당 1콜이라 개발계정(일 1,000건)으로는 이틀 걸린다.
한도에 걸리면 **거기까지 저장하고 멈춘다.** 다음 날 다시 실행하면 이어서 받는다.
운영계정(일 100,000건)이면 한 번에 끝난다.

조건이 바뀌면 다시 실행해 재커밋하면 된다.
